# 公众号文风 Skill

版本：0.1.0 独立用户版。用自己的观点和材料，写一篇讲得清楚、适合自己表达的完整公众号文章。可学自己的样本，也可从没有样本的第一篇开始，通过具体改稿校准。

适合有真实观点但写得散、不像自己、段落缺少承接的作者。不负责编造观点和案例，不自动制作封面、配图、平台排版或发表。

## 材料和写法

| 材料 | 是否必需 | 怎样写 |
|---|---|---|
| 本篇想法和事实 | 必需，可粘贴 | 给谁看、核心看法、实际做过什么、哪些结果已知、篇幅或用途 |
| 个人表达样本 | 可选 | 有权使用的连续片段，标明只学表达；事实也想用于本篇时另行说明 |
| 待改正文和反馈 | 改稿时提供 | 给上下文、哪段不对、实际意思和只改哪里 |
| 作者表达记录 | 接续时可选 | 上轮实际保存的偏好及适用范围；没有就从本轮开始 |

不要把多份材料混在一起而不标用途。不要求先建知识库或结构卡；旧文的客户、数字、经历不自动进入本篇。

## 完整合成示例

以下仅为练习，不代表真实客户或效果：

```text
用 $hanxu-public-account-voice 给独立设计师写一篇公众号文章。
本题观点：客户说“改一点”时，先把范围问清楚，再决定怎样接。
本题事实：第一次我直接答应，后来发现要重做页面结构。第二次我先请客户圈出位置，问希望解决什么，才发现只是想让价格更明显。我确认只改价格区域后才开始。客户说满意，没有成交效果数据。
文风样本，仅学说法，不带入事实：我以前总想把话一次讲全。结果呢，对方越听越不知道先做什么。现在我先讲眼前这个问题，其他的，等真用到再说。
请交完整正文，保留我的明确判断，别加亲测成绩。不需要标题、分析或封面。
```

无样本可删掉该行继续。材料够时直接交正文，影响中心判断的缺口才补问。返修可说：“第三段太绕，只改这一段，保留事实与结尾。”一次要求默认只影响本篇，明确长期要求才记为偏好。

## 安装和使用

取得完整 `hanxu-public-account-voice` 文件夹后交给自己的AI助手安装，保留配套文件。有旧版先备份到技能发现目录外，不覆盖作者资料、其他Skill或任务文件；让助手读回名称、版本和实际位置。未识别按宿主安装说明恢复，不假装已加载。

安装后用 `$hanxu-public-account-voice` 加自己的材料开始。只需能读完整Skill的AI助手，核心写稿不需Python、平台登录或额外API密钥。AI服务费用按自己的账号承担，资料由所选AI服务处理，不自动上传到其他平台。

## 安装包和成果

| 文件 | 用途 | 要修改吗 |
|---|---|---|
| `SKILL.md` | 独立成稿入口与接续 | 通常不用 |
| `references/证据整理.md` | 本题事实及公开边界 | 通常不用 |
| `references/论证结构.md` | 文章论证与递进 | 通常不用 |
| `references/正文写作.md` | 完整文章和局部返修 | 通常不用 |
| `references/个人文章表达校准.md` | 样本、偏好和新题接续 | 通常不用 |
| `references/成稿执行标准.md` | 最终正文检查 | 通常不用 |
| `agents/openai.yaml`、`VERSION`、`SKILL-MANIFEST.json` | 发现、版本与文件校验 | 通常不用 |
| `README.md` | 本说明与合成示例 | 通常不用 |

得到一篇可复制、待作者确认的完整正文。后台处理证据、结构和校准，实际复核最弱段落。需要作者记录时保存到指定工作目录；无文件能力则提供可粘贴续接说明，不声称已存盘。

文风相似、论证成立、真人采用和发表效果分别验证；不能保证首稿完全像本人或带来阅读提升。实际验证范围见 VALIDATION.md，安装或文件检查不代表所有模型成稿质量通过。反馈提供版本、去敏材料与具体问题句段，不需完整客户档案。

## 练习得到的实际结果

以下结果来自本轮明确合成材料，不是客户效果或外部用户认可。

合成练习的正文片段：

> 客户说改一点，我现在会先问清楚，再答应。
>
> 以前我不是这样。对方说只改一点，我就接了。等到真正动手，才发现要改的是页面结构。前面答应得很快，后面却得重新判断整件事。

收到“第三段更像当面说话，只改这一段”后，实际替换为：

> 客户说的一点，可能只是他觉得不满意的那个地方。可落到设计上，要动的东西未必少。先别把这句话当成工作量，问清楚到底改哪儿、想解决什么，再判断。

其他段落保持原文；样本中的旧事实没有进入本题。相似度仍需作者本人判断。
